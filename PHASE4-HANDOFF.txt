 FEATURES DESIGNED

✅ HQ PICKUP TAB
   - All office orders in ASSIGNED status
   - Grid of order cards (customer, boxes, barcode)
   - Filter by office, driver, date range
   - Real-time auto-refresh on new assignments
   - Expandable details (box list, activity trail)
   - Sort by date, driver, office

✅ HQ DROPOFF TAB
   - Live tracking of orders in PICKED_UP/IN_TRANSIT status
   - Progress bars (boxes delivered %)
   - Driver info (name, phone, location)
   - Real-time subscription updates
   - Alert for stalled orders (>4h)
   - Same filters as Pickup tab

✅ HQ COMPLETED TAB
   - Shipment history (DELIVERED/COMPLETED)
   - Table view with sortable columns
   - Columns: Order ID, Customer, Driver, Boxes, Date, Payment
   - Expandable box details
   - Payment status badges (Paid/Pending)
   - Pagination (25-50 rows per page)
   - CSV export button
   - Activity trail for each order

✅ ADVANCED FILTERS
   - Office (dropdown)
   - Driver (dropdown)
   - Status (tab-specific)
   - Payment status (Paid/Unpaid/Pending)
   - Date range (ISO dates)
   - Search (quick lookup by ID/customer)
   - Sort options (by date, driver, office)
   - Reset button (clear all)

✅ REAL-TIME SYNC
   - Subscribe to box_orders changes
   - Subscribe to activity_log INSERTs
   - Auto-refresh tabs on status changes
   - Proper cleanup (unsubscribe on unmount)

✅ SECURITY & RLS
   - Leverages Phase 1 HQ role (Supabase auth)
   - RLS policies enforce multi-tenant isolation
   - No client-side access control (server enforces)

   - Auth check (non-HQ users denied)

 ARCHITECTURE HIGHLIGHTS
═══════════════════════════════════════════════════════════════════════════════

Component Structure:
  HQUnifiedTabs (main)
  ├─ TabNavigation (3 buttons)
  ├─ PickupTab (+ OrderCard)
  ├─ DropoffTab (+ DropoffCard)
  └─ CompletedTab (+ CompletedTable)

State Management:
  FilterContext (Redux-like reducer)
  - office_id, driver_id, status, payment_status
  - date_from, date_to, search_text, sort_by
  - page, page_size

Services:
  - SupabaseQueries (12 functions, copy-paste ready)
  - RealTimeService (subscriptions, cleanup)
  - FilterContext (state + dispatch)

Data Flow:
  UI (filters) → FilterContext → SupabaseQueries → Supabase
                                     ↓
                              RealTimeService (subscriptions)
                                     ↓
                         Update UI on new data

═══════════════════════════════════════════════════════════════════════════════
 PHASE 1 DEPENDENCIES
═══════════════════════════════════════════════════════════════════════════════

✅ box_orders table (Phase 1)
   - Columns: id, order_id, box_number, status, office_id, driver_id, barcode, 
     weight_lbs, created_at, updated_at, status_updated_at
   - Indexes: status, driver_id, office_id, created_at
   - RLS: HQ can SELECT all

✅ activity_log table (Phase 1)
   - Columns: id, order_id, box_id, user_id, activity_type, action, 
     description, old_data, new_data, created_at
   - RLS: HQ can SELECT all, only INSERT allowed (immutable)

✅ orders table (Phase 0, extended Phase 1)
   - Columns: id, customer_name, recipient_name, recipient_address, 
     recipient_phone, pickup_location, payment_status, updated_at
   - Relationships: FK to box_orders

✅ RLS Policies (Phase 1)
   - HQ role: Can SELECT all rows without filtering
   - Office role: Can SELECT own office rows
   - Driver role: Can SELECT assigned boxes
   - Anonymous: Denied access
